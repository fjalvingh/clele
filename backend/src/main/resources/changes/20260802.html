Inviting people, instead of adding them

An Organisation Admin no longer adds people to an organisation directly. The Users screen has a new Invite user button: type the email address of the person you want, tick what they should be allowed to do in this organisation, and send it. They receive a mail naming you and the organisation, with a link to accept or refuse.

While you type the address, the name of the account behind it appears underneath, so you can see you are inviting the person you meant. If they are already a member, or already have an invitation outstanding, it says so and the button is disabled.

The reason for the change is consent: the old Add existing user button let one organisation's administrator pull in anyone whose email address they happened to know, without that person ever being asked. Now the invitee decides. Only when they accept do they join, and only then do the permissions you chose take effect.

If the invitee has no account yet, one is created for them when they accept — they are asked for their name, phone number and a password on the spot. If they already have an account, nothing about it changes: accepting only adds the new organisation.

Every invitation you have sent is listed under the member table, with its status — awaiting reply, accepted, refused, withdrawn or expired. Outstanding ones can be withdrawn with Withdraw. Invitations expire after two weeks.

Accounts are managed in one place

Creating, editing and deleting a user account now happens only on All Users, the Global Administrator's screen. That screen gained a + New User button (pick the organisations the account belongs to — at least one) and a Delete action per row.

The Users screen keeps everything that is genuinely about this organisation: who is in it, what they may do here, removing them from it, and deleting the parts they created. Its New User, Edit and Add existing user buttons are gone — an email address identifies one person across the whole installation, so an account was never an organisation's to create.

For administrators: sending mail

Invitation mails need an SMTP server. Set MAIL_HOST (and where needed MAIL_PORT, MAIL_USERNAME, MAIL_PASSWORD, MAIL_FROM) in the environment. Set APP_BASE_URL to the address users reach the app on if it sits behind a proxy; otherwise the link is built from the request.

Without a mail server configured nothing breaks: the invitation is still created, and the dialog shows you the link to pass on yourself.
